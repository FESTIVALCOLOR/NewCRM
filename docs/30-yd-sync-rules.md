# Правила синхронизации файлов с Яндекс.Диском

## Архитектура хранения файлов

### Два хранилища (историческое наследие)
1. **Поля в таблице `contracts`** — десктоп читает отсюда (contract_file_link, tech_task_link, act_*_link и т.д.)
2. **Таблица `project_files`** — мобиль читает отсюда (универсальная, множественные файлы)

**Правило:** при загрузке/удалении файла — обновлять ОБА хранилища.

### Маппинг stage → поля contracts

| Stage | Поля contracts (link / yandex_path / file_name) |
|-------|------------------------------------------------|
| `documents` | contract_file_* |
| `tech_task` | tech_task_* |
| `measurement` | measurement_image_link / measurement_yandex_path / measurement_file_name |
| `stage1` | act_planning_* |
| `stage2_concept` | act_concept_* |
| `stage3` | act_final_* |
| `stage1_signed` | act_planning_signed_* |
| `stage2_signed` | act_concept_signed_* |
| `stage3_signed` | act_final_signed_* |
| `supervision` (доп. соглашения) | additional_agreement_* |

### CRM карточки и Надзор
- Файлы стадий (stage1, stage2_concept, stage2_3d, stage3) → только `project_files`
- Надзор → только `project_files`

## Структура папок на Яндекс.Диске

### Формат пути
```
disk:/CRM/Проекты/{АГЕНТ}/{ТИП}/{ГОРОД}/{ГОРОД-Адрес-Площадьм2}/
```

**Площадь** — как Python float: `100.0`, `95.5`. В JS: `Number(area).toFixed(1)`.

### Подпапки (создаются автоматически)
```
{папка договора}/
├── Документы/
│   ├── Акты/
│   ├── Информационные письма/
│   └── Доп. соглашения/
├── Анкета/                              ← ТЗ
├── Замер/
├── Референсы/
├── Фотофиксация/
├── 1 стадия - Планировочное решение/
├── 2 стадия - Концепция дизайна/
│   ├── Концепция-коллажи/
│   └── 3D визуализация/
└── 3 стадия - Чертежный проект/
```

### Города — ТОЛЬКО коды
- Москва → `МСК`
- Санкт-Петербург → `СПБ`
- Великий Новгород → `ВН`
- Екатеринбург → `ЕКТ`

## Синхронизация CRM → ЯД (прямая)

### При загрузке файла (мобиль)
1. `ensureYdFolder()` — проверяет/создаёт папку
2. Загрузка на ЯД через `filesApi.upload()`
3. Создание записи в `project_files`
4. Обновление соответствующих полей в `contracts` (для десктопа)

### При удалении файла
1. Удаление записи из `project_files`
2. Очистка полей в `contracts`

### При изменении данных договора
1. Генерация нового пути `buildYdFolderPath()`
2. `move-folder` (переименование) или `create-folder`
3. Обновление `yandex_folder_path` в БД
4. Создание подпапок `createYdSubfolders()`
5. Обновление путей в `project_files` и полях `contracts` (серверный move-folder)

## Синхронизация ЯД → CRM (обратная)

### Серверный endpoint: `POST /api/v1/files/scan/{contract_id}`

1. Рекурсивный обход папки договора на ЯД
2. Маппинг подпапок → stage (точный + нечёткий)
3. **Классификация по имени файла** (`classify_document_by_name`):
   - `акт пр`, `планировоч` → `stage1`
   - `акт кд`, `концепц`, `дизайн` → `stage2_concept`
   - `акт рч`, `чертеж`, `финал` → `stage3`
   - `подпис`, `signed` → `*_signed` варианты
   - `договор`, `contract` → `documents`
   - `информ`, `письм` → `info_letter`
   - `доп`, `соглашен` → `supervision`
4. Извлечение вариаций: `Вариация N` → `variation=N`
5. Создание записей в `project_files` (с защитой от дубликатов)
6. Обновление полей `contracts` для совместимости с десктопом
7. Пропуск нераспознанных папок (логирование)

### Автопроверка при открытии карточки
- При открытии ContractDetailPage / CrmCardPage
- Фоновая проверка каждого файла через `getPublicLink`
- Если файл не найден на ЯД → удаление записи из БД + уведомление

### Кнопка «Синхронизировать»
- **Мобиль**: голубая круглая кнопка (round, icon=sync) рядом с FAB edit
- **Десктоп**: зелёная квадратная кнопка (36x36, icon=refresh-white) рядом с диагностикой
- Действия: проверка/создание/переименование папки → scan → удаление мёртвых записей

## API endpoints

| Endpoint | Метод | Описание |
|----------|-------|---------|
| `/api/v1/files/folder` | POST | Создать папку на ЯД |
| `/api/v1/files/move-folder` | POST | Переименовать папку + обновить пути в БД |
| `/api/v1/files/scan/{contract_id}` | POST | Обратная синхронизация ЯД → БД |
| `/api/v1/files/public-link` | GET | Получить публичную ссылку |
| `/api/v1/files/list` | GET | Листинг файлов папки |

---

## Важные правила

1. **`yandex_folder_path` в БД = единый источник правды** для обеих версий
2. **НЕ использовать `/api/v1/files/create-folder`** — правильный URL: `/api/v1/files/folder`
3. **Площадь в пути** — всегда `.toFixed(1)` в JS (совпадает с Python float)
4. **При move-folder** — серверный endpoint автоматически обновляет пути в `project_files` и `contracts`
5. **Классификация по имени** — best-effort, fallback на stage родительской папки
