# Диагностика мобильной версии CRM
**Дата:** 27 марта 2026

Сравнили мобильную версию с десктопом (десктоп = эталон). Нашли баги, недоделки, и составили план что чинить.

---

## 1. БАГИ (сломано, нужно чинить срочно)

### Баг 1 — Кнопка "Клиент согласовал" не работает
- **Где:** мобилка, кнопка "Клиент согласовал" в карточке CRM
- **Что происходит:** при нажатии — ошибка 404 (страница не найдена)
- **Почему:** мобилка отправляет запрос на адрес `client-approved`, а сервер ждёт запрос на адрес `client-ok`. Просто разные названия — опечатка
- **Последствия:** проект НЕВОЗМОЖНО провести через согласование клиентом с телефона. Это основной бизнес-процесс
- **Где исправить:** файл `mobile/src/services/api.js`, строка 96 — заменить `client-approved` на `client-ok`
- **Время:** 5 минут

### Баг 2 — Совместитель "Руководитель студии" не получает полные права
- **Где:** мобилка, система прав доступа
- **Что происходит:** если у сотрудника основная должность "Менеджер", а дополнительная "Руководитель студии" — в мобилке он видит только менеджерские функции
- **Почему:** мобилка проверяет только основную должность, а дополнительную игнорирует. Десктоп проверяет обе
- **Последствия:** совместитель не видит страницы Администрирования, не может управлять правами и т.д.
- **Где исправить:** файл `mobile/src/stores/permissions.js`, строка 17 — добавить проверку `secondary_position`
- **Время:** 5 минут

### Баг 3 — Старший менеджер не видит страницы "Администрирование" и "Файлы"
- **Где:** мобилка, меню навигации
- **Что происходит:** у Старшего менеджера есть право `access.admin`, но в мобилке страницы Админки и Файлов всё равно не показываются
- **Почему:** эти страницы привязаны только к роли "суперпользователь", а не к конкретному праву доступа. В десктопе работает правильно
- **Последствия:** Старший менеджер не может управлять тарифами, агентами, городами, ролями с телефона
- **Где исправить:** файл `mobile/src/stores/permissions.js`, строка 38 — проверять право `access.admin` вместо роли суперпользователя
- **Время:** 10 минут

### Баг 4 — При отметке "Оплачено" записывается несуществующий сотрудник
- **Где:** мобилка, страница Зарплаты, кнопка "Оплатить"
- **Что происходит:** если по какой-то причине ID сотрудника не передался — система записывает `paid_by = 0` (сотрудника с ID=0 не существует)
- **Почему:** в коде стоит `employeeId || 0` — то есть при пустом значении подставляется 0 вместо того чтобы взять ID текущего пользователя
- **Последствия:** в базе появляется "мусорная" запись, непонятно кто отметил оплату
- **Где исправить:** файл `mobile/src/services/api.js`, строка 224 — брать ID из текущей сессии
- **Время:** 10 минут

## 2. НЕДОДЕЛКИ (работает, но функций меньше чем в десктопе)

### Зарплаты и платежи
- **Нельзя отредактировать платёж** — только создать, удалить или поменять статус. Если менеджер ошибся в сумме — нужно удалить и создать заново. В десктопе есть кнопка "Редактировать"
- **Расчёт по тарифам не подключен** — на сервере есть готовая функция расчёта, но мобилка её не использует

### CRM — работа с проектами
- **Нельзя переназначить исполнителя без перемещения карточки** — если дизайнер заболел и нужно заменить его на другого на той же стадии, в десктопе есть отдельная кнопка. В мобилке — нет
- **При отправке "На исправление" нельзя приложить файл** — в десктопе можно приложить скриншот или PDF с пометками, в мобилке только текстовый комментарий
- **Нет проверки оплаты аванса** — в десктопе при перемещении карточки на рабочую стадию проверяется, оплатил ли клиент аванс. В мобилке этой проверки нет

### Telegram-мессенджер
- **Полностью отсутствует** — в десктопе есть создание проектных чатов в Telegram, автоматические скрипты сообщений клиентам, отправка актов. В мобилке ничего из этого нет (0%)

### Блокировки при редактировании
- **Нет защиты от одновременного редактирования** — если два человека откроют одну карточку и будут редактировать одновременно — чьи-то изменения потеряются. В десктопе есть блокировки

### Уведомления
- **Нельзя прочитать все уведомления одной кнопкой** — если накопилось 50 непрочитанных, нужно нажимать на каждое по очереди

### Профиль
- **Нельзя редактировать свой профиль** — сотрудник не может поменять телефон или email с телефона. Только просмотр

### Сотрудники
- **Нет поля "Адрес проживания"** — если создать сотрудника через мобилку, адрес не сохранится

### Логика фильтрации
- **Дизайнер видит лишние карточки** — из-за слишком широкого фильтра дизайнер может видеть карточки на стадии "3д визуализация" в шаблонных проектах, хотя не должен

## 3. ПРОБЛЕМЫ С ИНТЕРНЕТОМ И СИНХРОНИЗАЦИЕЙ

- **Нет работы без интернета** — в десктопе при пропадании сети можно продолжать работать, все действия сохраняются в очередь и отправляются когда сеть вернётся. В мобилке при пропадании сети — просто белый экран "Нет соединения"
- **Ненадёжное определение интернета** — мобилка использует стандартный браузерный индикатор, который может показывать "есть интернет" когда Wi-Fi подключен, но интернета нет
- **Данные не обновляются автоматически** — нужно вручную тянуть экран вниз (pull-to-refresh) чтобы увидеть свежие данные. В десктопе данные обновляются при переключении вкладок

## 6. ИДЕИ ДЛЯ УЛУЧШЕНИЙ (не баги, а новые возможности)

1. **Мгновенные обновления** — сейчас данные обновляются раз в минуту. Можно сделать мгновенно через WebSocket (как в мессенджерах)

2. **Быстрый отклик интерфейса** — при нажатии кнопки сначала показывать результат, а потом отправлять на сервер. Если ошибка — откатывать. Сейчас пользователь ждёт ответа сервера

3. **Фото с камеры** — замерщик или ДАН фотографирует объект прямо из приложения, фото автоматически попадает на Яндекс.Диск в нужную папку. Сейчас нужно сфотографировать отдельно, потом загрузить файл

4. **Push-уведомления** — получать уведомления на телефон даже когда приложение закрыто (как в WhatsApp)

5. **Вход по Face ID / отпечатку** — вместо логина и пароля каждый раз

6. **QR-коды на объектах** — ДАН приезжает на объект, сканирует QR на двери → сразу открывается карточка проекта со всеми данными

7. **Голосовые заметки** — записать замечание голосом, оно автоматически расшифруется в текст и сохранится в историю

8. **Интеграция с календарём** — дедлайны проектов автоматически появляются в Google/Apple календаре с напоминаниями

9. **Быстрые действия** — при долгом нажатии на иконку приложения показывать: "Мои задачи", "CRM доска", "Сканировать QR"

10. **Работа без интернета** — полноценная работа на объекте даже без связи, всё синхронизируется когда появится интернет
