# Исследование: Перестройка стратегии тестирования

**Дата:** 2026-03-06
**Статус:** Исследование завершено. Готов к запуску /orkester для планирования.
**Детали:** [docs/plan/testing-strategy-overhaul/research.md](plan/testing-strategy-overhaul/research.md)

## Краткие выводы

### Проблема
8997 тестов, из них:
- **73% (6590)** — моки, не ловят ничего реального
- **14% (1222)** — smoke/e2e по API, проверяют `status_code == 200`, НЕ данные
- **0%** — тестируют что ВИДИТ пользователь в UI

### Решение: 4 слоя реального тестирования

| Слой | Инструмент | Что ловит | Оценка |
|------|-----------|-----------|--------|
| API Fuzzing | **Schemathesis** | 500 ошибки, validation bypass, edge cases | 10/10 |
| Data Validation | **Умные smoke-тесты** | area=0, amount=null, сиротские записи | 10/10 |
| UI Widgets | **pytest-qt + реальный DataAccess** | Данные не загрузились, кнопка не работает | 9/10 |
| Property-based | **Hypothesis** | NaN, деление на 0, overflow в расчётах | 9/10 |
| Running App | **pywinauto (accessibility tree)** | Кнопка не кликается, таблица пуста, модальный блок | 7/10 |
| AI Visual QA | **Claude Code + скриншоты** | Поле перекрыто, дата не видна | 6/10 |

**Не подходят:** Playwright (только браузер), Appium (WinAppDriver заморожен Microsoft), testRigor (платный SaaS)

### Что делать с мок-тестами (6590 штук)
НЕ удалять. Они ловят regression при рефакторинге в CI. Но поверх них добавить реальные тесты.
