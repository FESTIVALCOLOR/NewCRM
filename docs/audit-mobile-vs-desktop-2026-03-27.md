# Аудит: Мобильная версия vs Десктоп — Interior Studio CRM
**Дата:** 27 марта 2026
**Метод:** 3-итерационный анализ с параллельными агентами (8 субагентов)
**Эталон:** Desktop (PyQt5) — ультимативный стандарт

---

## Общая оценка

Мобильная PWA версия покрывает **~85% функционала** десктопа. Основные бизнес-процессы (CRM доска, работа с карточками, платежи, надзор) работают. Однако есть **12 критических** и **15 значимых** расхождений, которые влияют на полноценную работу.

**Мобильная версия включает:** 20 страниц, 12 компонентов, 8 stores, 5 composables, WebSocket real-time.

## РАЗДЕЛ 5: СИСТЕМА УВЕДОМЛЕНИЙ (Подробный разбор)

### Как работают уведомления

**Триггеры уведомлений (когда ПРИХОДЯТ):**

| Событие | Кому | Тип |
|---------|------|-----|
| Создание CRM карточки | Ст. менеджер | assigned |
| Назначение исполнителя | Исполнитель (дизайнер/чертежник) | assigned |
| Назначение СДП/ГАП/Менеджера | Соответствующий сотрудник | assigned |
| Сдача работы исполнителем | Проверяющий (СДП/ГАП/Менеджер) | crm_stage |
| Отправка клиенту | Ст. менеджер (дубль) | crm_stage |
| На исправление | Исполнитель | crm_stage |
| Клиент согласовал | Ст. менеджер | crm_stage |
| Акт подписан | Команда проекта | crm_stage |
| За 2 рабочих дня до дедлайна | Исполнитель + проверяющий | deadline |
| Просрочка дедлайна | Исполнитель + ст. менеджер + проверяющий | deadline |
| Создание платежа | Ст. менеджер | payment |
| Создание карточки надзора | Ст. менеджер | supervision |
| Планирование выезда | ДАН | supervision |

**Когда уведомления ДОЛЖНЫ перестать приходить:**

| Условие | Работает? |
|---------|-----------|
| Сотрудник отключил тип в настройках | ✅ Да |
| Сотрудник отключил Telegram | ✅ Да |
| Не заполнен telegram_user_id | ✅ Да (создаётся в БД, но не отправляется) |
| Стадия завершена (completed) | ✅ Да (проверка completed == False) |
| Один раз в день (защита от спама) | ✅ Да (_sent_today set) |

**Правила дублирования (4 правила):**
1. Уведомление ст. менеджеру → дублируется Руководителю + Менеджеру
2. Уведомление СДП/ГАП → информационный дубль ст. менеджеру (без фраз действия)
3. Уведомление исполнителю об исправлениях → информационный дубль ст. менеджеру
4. Шаблонные проекты: уведомление Менеджеру/ГАП → информационный дубль ст. менеджеру

### Что работает правильно

| Функция | Статус | Комментарий |
|---------|--------|-------------|
| Список уведомлений (mobile) | ✅ Работает | Фильтр Все/Непрочитанные, навигация по клику |
| Отметить прочитанным | ✅ Работает | Автоматически при клике |
| WebSocket real-time | ✅ Работает | Новые уведомления приходят мгновенно |
| Иконки по типам | ✅ Работает | assigned, deadline, payment, crm_stage, supervision |
| Проверка дедлайнов | ✅ Работает | Background task каждые 4 часа |
| Защита от рекурсии дублей | ✅ Работает | Флаг is_duplicate + set already_sent |
| Защита от спама (1/день) | ✅ Работает | _sent_today set сбрасывается при смене даты |

### Что НЕ работает или отсутствует

| # | Проблема | Серьёзность | Описание | Решение |
|---|----------|-------------|----------|---------|
| 17 | **Нет endpoint mark-all-read** | 🔴 Критично | Mobile вызывает POST /notifications/mark-all-read, но endpoint НЕ СУЩЕСТВУЕТ на сервере. Кнопка "Прочитать все" не работает | Добавить endpoint в notifications_router.py |
