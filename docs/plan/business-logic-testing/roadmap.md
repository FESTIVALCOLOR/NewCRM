# Дорожная карта: тестирование бизнес-логики Interior Studio CRM

## Проблема

Существующие тесты проверяют:
- Паттерны в исходном коде (threading, None-safety, импорты)
- Контракты API (ключи ответов, типы данных)
- E2E эндпоинты (HTTP статусы)

Но НЕ проверяют:
- **Правильность расчётов** (платежи, тарифы, norm_days)
- **Бизнес-правила переходов** (CRM стадии, workflow)
- **Целостность данных** (payment_status vs is_paid, reassigned)
- **Граничные случаи** (площадь >500м², нулевые тарифы, пустые стадии)
- **Реальные сценарии** (создать договор → карточку → назначить → рассчитать → оплатить)

## Архитектура тестирования

```
tests/
  business/                    # НОВАЯ ДИРЕКТОРИЯ
    test_payment_calculation.py     # Фаза 1: расчёт платежей
    test_timeline_calculation.py    # Фаза 2: расчёт сроков
    test_crm_workflow.py            # Фаза 3: CRM переходы
    test_supervision_workflow.py    # Фаза 4: надзор
    test_data_integrity.py          # Фаза 5: целостность данных
    test_salary_report.py           # Фаза 6: отчёт по зарплатам
    conftest.py                     # Фикстуры: контракты, карточки, тарифы
```

## Фаза 1: Расчёт платежей (КРИТИЧНО)
**Файл:** `tests/business/test_payment_calculation.py`
**Цель:** Проверить формулы расчёта для ВСЕХ комбинаций

### Тесты:

#### 1.1 Индивидуальный проект — расчёт по площади
```
Дано: contract.area=120, project_type='Индивидуальный', role='Дизайнер'
      Rate: rate_per_m2=500
Ожидаем: amount = 120 * 500 = 60000
```
- Обычная площадь (50-100 м²)
- Площадь 1 м² (минимум)
- Площадь 500 м² (граница)
- Площадь 501 м² (баг: >500м² ранее считалось неправильно)
- Площадь 0 м² → amount=0 (не отрицательный)

#### 1.2 Шаблонный проект — фиксированная цена
```
Дано: contract.area=80, project_type='Шаблонный', role='Дизайнер'
      Rate: area_from=50, area_to=100, fixed_price=45000
Ожидаем: amount = 45000 (фиксированная)
```
- Площадь попадает в диапазон
- Площадь НЕ попадает ни в один диапазон → amount=0
- Площадь на границе (area=area_from, area=area_to)
- Нет тарифа для этой роли → amount=0

#### 1.3 Авторский надзор — расчёт по площади
```
Дано: supervision_card_id=10, area=120, role='ДАН'
      Rate: project_type='Авторский надзор', rate_per_m2=300
Ожидаем: amount = 120 * 300 = 36000
```

#### 1.4 Замерщик — фиксированная цена по городу
```
Дано: role='Замерщик', city='СПБ'
      Rate: surveyor_price=5000
Ожидаем: amount = 5000
```
- Город СПБ, МСК, ВН (разные цены)
- Неизвестный город → amount=0

#### 1.5 СДП — два платежа (Аванс 50% + Доплата 50%)
```
Дано: role='СДП', area=100, rate_per_m2=400
Ожидаем: Аванс=20000, Доплата=20000 (50/50 от 40000)
```

#### 1.6 Тариф не найден
```
Дано: role='НесуществующаяРоль'
Ожидаем: amount=0, НЕ crash
```

#### 1.7 calculated_amount vs final_amount
```
Дано: calculated_amount=60000, ручное изменение final_amount=55000
Ожидаем: is_manual=True, final_amount=55000 (не перезаписывается calculated)
```

## Фаза 2: Расчёт сроков (Timeline)
**Файл:** `tests/business/test_timeline_calculation.py`
**Цель:** Проверить формулы norm_days, actual_days, START дата

### Тесты:

#### 2.1 Коэффициент площади K
```
area=50  → K=0
area=100 → K=0
area=101 → K=1
area=200 → K=1
area=201 → K=2
area=500 → K=4
area=501 → K=5
```

#### 2.2 START дата проекта
```
Дано: contract_date='2026-01-15', survey_date='2026-01-20',
      tech_task_date='2026-01-18'
Ожидаем: START = '2026-01-20' (максимум из всех дат)
```
- Все даты одинаковые
- Одна дата None → игнорируется
- Все даты None → contract_date

#### 2.3 Рабочие дни (networkdays)
```
Дано: start='2026-01-19' (пн), end='2026-01-23' (пт)
Ожидаем: 5 рабочих дней
```
- Через выходные (Сб-Вс не считаются)
- Через праздники РФ (01.01, 08.03, 01.05, 09.05)
- start=end → 0 или 1 день
- start > end → 0 (не отрицательный)

#### 2.4 Пропорциональное распределение norm_days
```
Дано: contract_period=60, raw_norm_days=[12, 28, 20], sum=60
Ожидаем: [12, 28, 20] (без изменений, сумма = период)

Дано: contract_period=30, raw_norm_days=[12, 28, 20], sum=60
Ожидаем: [6, 14, 10] (пропорция 30/60)
```

#### 2.5 Actual days между датами
```
Дано: dates=['2026-01-20', '2026-01-24', '2026-02-03']
Ожидаем: actual_days=[0, 4, 8] (рабочие дни между)
```

## Фаза 3: CRM Workflow (переходы карточек)
**Файл:** `tests/business/test_crm_workflow.py`
**Цель:** Проверить правила переходов между колонками

### Тесты:

#### 3.1 Последовательность колонок
```
'Новый заказ' → 'Стадия 1' — OK (вперёд)
'Стадия 1' → 'Стадия 3' — ЗАПРЕЩЕНО (пропуск)
'Стадия 2' → 'Стадия 1' — ЗАПРЕЩЕНО (назад)
'Стадия 1' → 'В ожидании' — OK (пауза)
'В ожидании' → previous_column — OK (возврат)
```

#### 3.2 Пауза и возврат
```
Дано: card в 'Стадия 1', ставим паузу
Ожидаем: column='В ожидании', previous_column='Стадия 1'

Возврат:
Ожидаем: column='Стадия 1', total_pause_days увеличен
```

#### 3.3 Пересчёт дедлайна после паузы
```
Дано: deadline='2026-03-01', paused_at='2026-02-15', resumed='2026-02-20'
      pause_days = 3 рабочих дня
Ожидаем: deadline='2026-03-04' (сдвинут на 3 рабочих дня)
```

#### 3.4 Исполнитель workflow
```
submit → completed=True, submitted_date=now
accept → completed_date=now
reject → completed=False, revision_count++
```

#### 3.5 Согласование с клиентом
```
client-send → status='client_approval'
client-ok → status='completed'
```

#### 3.6 Свободное перемещение (руководство)
```
role='Директор' → можно перемещать в любую колонку
role='Дизайнер' → только по порядку
```

## Фаза 5: Целостность данных
**Файл:** `tests/business/test_data_integrity.py`
**Цель:** Проверить инварианты данных на РЕАЛЬНОМ сервере (E2E)

### Тесты:

#### 5.1 payment_status ↔ is_paid синхронизация
```
Для каждого платежа на сервере:
  if is_paid=True  → payment_status ДОЛЖЕН быть 'paid'
  if is_paid=False → payment_status НЕ ДОЛЖЕН быть 'paid'
```

#### 5.2 CRM карточки без контракта
```
Для каждой CRM карточки:
  contract_id ДОЛЖЕН ссылаться на существующий контракт
```

#### 5.3 Платежи с reassigned=True
```
Для каждого reassigned платежа:
  ДОЛЖЕН существовать новый платёж для нового исполнителя
```

#### 5.4 Суммы не отрицательные
```
Для каждого платежа:
  final_amount >= 0
  calculated_amount >= 0
```

#### 5.5 report_month формат
```
Для каждого платежа:
  report_month IS NULL (в работе) ИЛИ matches 'YYYY-MM'
```

#### 5.6 StageExecutor deadline
```
Для каждого исполнителя:
  deadline >= assigned_date (дедлайн не раньше назначения)
```

#### 5.7 Архивные карточки
```
Для каждого контракта со статусом 'СДАН'/'РАСТОРГНУТ':
  CRM карточка ДОЛЖНА быть в 'Выполненный проект' или архиве
  НЕ должна быть в 'Стадия 1'/'Стадия 2' (активная работа)
```

## Фаза 6: Отчёт по зарплатам
**Файл:** `tests/business/test_salary_report.py`
**Цель:** Проверить группировку и суммирование

### Тесты:

#### 6.1 Группировка по report_month
```
payments с report_month='2026-02' → раздел "Февраль 2026"
payments с report_month=NULL → раздел "В работе"
```

#### 6.2 Суммирование по сотруднику
```
employee_id=5 имеет 3 платежа: 60000 + 45000 + 30000
Ожидаем: total_for_employee = 135000
```

#### 6.3 Фильтрация по типу
```
payment_type='Оклад' → включает salaries
source='CRM' → только CRM платежи
source='CRM Надзор' → только надзорные
```

#### 6.4 Оплаченные vs неоплаченные
```
is_paid=True → не показываются в "К оплате"
is_paid=False → показываются в "К оплате"
```

## Приоритеты

| Фаза | Приоритет | Причина |
|------|-----------|---------|
| 1. Платежи | КРИТИЧНО | Деньги. Ошибка в расчёте = финансовые потери |
| 5. Целостность | КРИТИЧНО | Рассинхрон данных = скрытые баги |
| 2. Сроки | ВЫСОКИЙ | Неверные дедлайны = срыв проектов |
| 3. CRM Workflow | ВЫСОКИЙ | Неверные переходы = сломанный процесс |
| 6. Зарплаты | ВЫСОКИЙ | Неправильный отчёт = ошибки в выплатах |
| 4. Надзор | СРЕДНИЙ | Аналогично CRM, но меньше пользователей |

## Метод тестирования

### Для фаз 1-4 (расчёты и workflow):
- **Unit-тесты** с моками DataAccess
- Подготовленные данные (контракт, тарифы, карточки)
- Проверка РЕЗУЛЬТАТА (суммы, даты, статусы), а не "вызвался ли метод"

### Для фазы 5 (целостность):
- **E2E тесты** против реального сервера
- Чтение РЕАЛЬНЫХ данных и проверка инвариантов
- Находит баги в СУЩЕСТВУЮЩИХ данных (не в тестовых)

### Для фазы 6 (зарплаты):
- **Интеграционные тесты** с реальным DataAccess
- Создание тестовых платежей → проверка отчёта → удаление

## Хронология

- **Фаза 1:** Расчёт платежей — первый приоритет
- **Фаза 5:** Целостность данных — параллельно с фазой 1
- **Фаза 2:** Сроки — после фазы 1
- **Фаза 3:** CRM Workflow — после фазы 2
- **Фаза 6:** Зарплаты — после фазы 3
- **Фаза 4:** Надзор — последний
