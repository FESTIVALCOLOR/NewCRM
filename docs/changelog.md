# Changelog — Interior Studio CRM

Журнал изменений приложения. Каждая версия содержит список изменений для публикации обновления.

---

## v1.0.1 — 2026-03-21

### Исправления ошибок

- **Тестовое уведомление** — обычные сотрудники теперь могут отправлять тестовое уведомление себе (раньше это мог только директор)
- **Зелёная рамка текущей стадии** — в диалоге «Данные проекта» зелёная рамка теперь корректно подсвечивает текущую стадию для всех трёх стадий (Планировочные решения, Концепция дизайна, Чертёжный проект), а не только для Стадии 2
- **Вкладка «Шаблонные проекты»** — исполнители (Дизайнер, Чертёжник) теперь видят вкладку «Шаблонные проекты» в CRM
- **Дедлайны подэтапов** — дедлайн на карточке канбана теперь обновляется для ВСЕХ подэтапов (ранее не обновлялся для клиентских шагов и подэтапов после 2.2)
- **Workflow: карточка застревала между подэтапами** — при согласовании клиентом диалог выбора действия больше нельзя закрыть без решения (убрана кнопка закрытия, заблокирован Escape). Добавлен retry при ошибке сети

### Новые возможности

- **Подсветка текущего подэтапа** — в таблице сроков (диалог карточки) текущий активный подэтап выделяется зелёным фоном, заголовок текущего блока подэтапов также подсвечивается зелёным
- **Чат: скрытие пустых ролей** — в welcome-скрипте чата строки с незаполненными ролями (когда сотрудник не назначен) автоматически скрываются
- **Чат: проверка обязательных ролей** — при создании чата проверяется наличие обязательных сотрудников:
  - Индивидуальный: Старший менеджер + СДП
  - Шаблонный: Старший менеджер + Менеджер
  - Надзор: Старший менеджер + Руководитель надзора

### Улучшения надёжности (серверная часть)

- **Централизованный workflow sync** — после каждого workflow-действия сервер автоматически проверяет и синхронизирует позицию карточки с реальным состоянием таймлайна. Это предотвращает «проваливание» карточки при переходах между подэтапами
- **Идемпотентный client-ok** — повторный вызов «клиент согласовал» (например, после краша приложения) не портит данные карточки
- **Retry при ошибке** — если серверный вызов workflow-действия не удался, предлагается повторить попытку (до 2 раз)

### Для руководителя студии

- **Кнопка диагностики карточки** (иконка гаечного ключа в диалоге карточки) — проверяет соответствие состояния карточки реальному таймлайну и восстанавливает при необходимости. Если карточка застряла между подэтапами — автоматически определит правильную позицию и переведёт в рабочее состояние. Показывает что именно было исправлено или подтверждает что всё в порядке
