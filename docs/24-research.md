# Фаза Research — Исследование контекста задачи

> Фаза 1 из 6 в конвейере оркестрации. Выполняется Research Agent (sonnet).

## Назначение

Фаза Research — это **исследование перед проектированием**. Агент анализирует место задачи в проекте, декомпозирует по 3 направлениям и создаёт документ с описанием текущего состояния.

**Ключевое правило:** ТОЛЬКО описание фактов — БЕЗ рекомендаций, решений, предложений.

## Когда выполняется

| Режим | Research |
|-------|----------|
| full | Полный (3 направления) |
| refactor | Полный (3 направления) |
| security | Lite (только архитектура) |
| fix | Пропускается |
| test | Пропускается |
| deploy | Пропускается |
| docker | Пропускается |
| qa | Пропускается |

## 3 направления исследования

### Направление 1: Архитектура

Анализ места задачи в архитектуре проекта:

- **Затронутые слои** — какие из 4 слоёв затронуты (server / ui / utils / database)
- **Двухрежимность** — как задача вписывается в online + offline архитектуру
- **Зависимости** — граф зависимостей между компонентами
- **Текущие контракты** — API endpoints, DataAccess методы, DB таблицы/поля
- **Затронутые файлы** — конкретные файлы:строки, которые будут изменены

### Направление 2: Паттерны

Анализ существующих паттернов для похожих задач:

- **Аналоги в кодовой базе** — существующие похожие реализации (с файлами и строками)
- **Используемые паттерны** — DataAccess, API-first, fallback, signal safety
- **Конвенции** — именование (snake_case, PascalCase), структура файлов
- **Шаблоны кода** — из shared-rules.md и docs/18-agent-skills.md

### Направление 3: Внешние интеграции

Анализ внешних зависимостей и ограничений:

- **API и сервисы** — какие внешние системы затронуты (REST API, Yandex.Disk, Telegram)
- **Зависимости и версии** — PyQt5, FastAPI, SQLAlchemy, Pydantic
- **Ограничения платформы** — Windows клиент, Linux сервер, Docker
- **Покрытие тестами** — текущее покрытие затронутых модулей

## Режим Lite (для security)

Упрощённый анализ — только направление "архитектура":
1. Определить затронутые файлы
2. Определить attack surface (endpoints, входные данные, авторизация)
3. НЕ анализировать паттерны и интеграции
