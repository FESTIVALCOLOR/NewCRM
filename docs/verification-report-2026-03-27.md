## Ошибки найденные при проверке и ИСПРАВЛЕННЫЕ

### Итерация 2 выявила 3 критические ошибки:

| # | Ошибка | Как исправлено |
|---|--------|---------------|
| 1 | **editNormDays: PATCH вместо PUT, entry.id вместо stage_code** — сервер принимает PUT с stage_code, а клиент слал PATCH с id. Нормо-дни НЕ сохранялись бы | Исправлено на `ax.put(...entry.stage_code)` с `encodeURIComponent` |
| 2 | **manager-acceptance: проверялось право complete_approval, а сервер требует move** — кнопка могла показываться пользователям без нужного права | Исправлено на `can('crm_cards.move')` |
| 3 | **deadline_checker: отсутствовала проверка `if not contract`** — для карточек без контракта мог быть exception | Добавлена проверка `if not contract: continue` |

## Оставшиеся различия Desktop vs Mobile (НЕ баги, а особенности)

### Это НОРМАЛЬНО для мобильной версии:

| Область | Desktop | Mobile | Почему так |
|---------|---------|--------|------------|
| Перетаскивание карточек | Drag-and-drop | Long-press + диалог | Мобильный интерфейс |
| Создание CRM карточки | Через диалог | Автоматически при создании договора | По задумке — карточка привязана к договору |
| Удаление CRM карточки | Есть | Нет (только архив) | Безопаснее для мобильного |
| Графики в отчётах | Сложные (Funnel, Stacked) | Упрощённые (Bar, Line, Pie) | Размер экрана |
| PDF экспорт | ReportLab (pixel-perfect) | Браузерная печать | Разные технологии |
| KPI цветовая кодировка | 4 уровня | Только значения | Упрощённый мобильный вид |
| Детальные KPI сотрудников | Тренды 6 мес., компоненты | Нагрузка и сравнение | Экономия места |
| completeApprovalStage | Используется | API есть, UI нет | Будет добавлено по необходимости |

### Система прав:
- Все 14 CRM-прав из desktop есть в mobile AdminPage
- Все проверки `can()` совпадают с серверными `require_permission()`
- Исключение (исправлено): manager-acceptance теперь проверяет `crm_cards.move`

### Система дедлайнов:
- Праздники РФ идентичны (14 дат) на клиенте и сервере
- Приостановка при согласовании: серверная логика работает, mobile перезагружает данные
- Пересчёт после паузы: серверная логика в client-ok работает правильно

### Система уведомлений:
- 5 типов событий: assigned, crm_stage, deadline, payment, supervision
- 4 правила дублирования работают
- Защита от спама: 1 уведомление/день на карточку
